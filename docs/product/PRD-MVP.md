# 1. Agent 产品介绍

## 1.1 产品定位

当前 MVP 聚焦产品/研发项目周会场景，基于飞书会议纪要/妙记、多维表格中的项目、任务、风险数据，以及项目主文档、周报、复盘材料，对项目型中层负责人在项目推进中的管理行为进行持续观察、证据校验、能力评估和风险提示，并输出结构化报告与改进建议。

本产品不是独立 App，也不是单轮问答机器人，而是运行在飞书内的“中层管理效能评估工作台 + Agent 自动化流程”。Base 承载项目、会议、评估任务、证据链、人工复核项和报告状态；飞书云文档承载正式报告；飞书消息承载任务触发、复核提醒和风险通知。

MVP 的核心业务闭环为：

`会议/文档/Base 数据进入 -> 事实结构化 -> 动态评估规划 -> 多 Agent 分析 -> 人工复核 -> 报告生成 -> Base 回写 -> 下一周期持续观察`

当前仓库实现态说明：

- 当前 MVP 已经跑通离线评估主链路，能够从样例输入包生成事实包、硬指标、专家结论、综合评分、最终报告和观测产物。
- 当前运行主形态是 `CLI/自动化触发 -> 工作流编排 -> 5 个 LLM Agent + 4 个规则/流程节点 -> JSON 成果物输出`，而不是完整在线 SaaS。
- 真实飞书在线拉数、在线回写、持久任务队列和审批闭环仍属于上线前待补能力；现阶段以 `report_result`、`base_writeback_payload` 和观测文档作为主要交付物。

## 1.2 功能介绍

1. 数据接入与事实结构化
   - 读取 Base 中的项目、任务、风险、评估结果和报告状态。
   - 读取会议纪要/妙记、项目主文档、周报、复盘和评审结论。
   - 将非结构化会议和文档内容转成可追踪的事件、发言、行动项、风险和证据索引。
2. 动态评估规划
   - 根据项目阶段、会议类型、风险状态和历史评估结果，判断本次应执行全量评估、轻量周报、专项风险审计还是组织行为复核。
   - 输出本次评估重点、需要运行的维度、人工复核规则和降级策略。
3. 五维管理能力评估
   - 围绕方向校准力、推进闭环力、风险治理力、协同调度力、组织行为健康度进行评估。
   - 每个维度输出结论、关键证据、置信度、风险标签和建议动作。
4. 证据链与置信度管理
   - 每条判断必须关联原始会议、Base 任务/风险、项目文档或历史记录。
   - 证据不足时输出“观察项”或“暂不判断”，不输出强定性结论。
5. 人工复核与审批
   - 对证据冲突、低置信度、高风险语言、敏感结论和可能影响管理决策的判断生成复核项。
   - HRBP、PMO、上级管理者可对 Agent 结论执行确认、驳回、降级、补充说明。
6. 报告生成与持续追踪
   - 输出摘要版、完整版、风险提示版报告。
   - 将评估结果、证据链、复核状态、报告链接和反馈入口写回 Base。
   - 下一周期评估时读取历史结论，观察管理行为是否改善。

## 1.3 评估对象及维度

### 1.3.1 评估对象

MVP 只覆盖单项目、单负责人、单周期评估：

- 评估对象：产品/研发项目中的项目型中层负责人。
- 评估场景：项目周会、风险复盘会、关键评审会、项目例会。
- 评估周期：默认单次会议 + 最近 3 到 5 场同项目历史会议复核；周期报告默认按周生成。
- 不做范围：不做跨项目横向排名，不做人事任免建议，不直接输出绩效定级。

### 1.3.2 一级维度总览

| 一级维度    | 业务定义                                           | MVP 关注重点                             |
| :------ | :--------------------------------------------- | :----------------------------------- |
| 方向校准力   | 管理者能否基于数据、文档、历史决议和项目事实校准方向，并在变化时清晰转向。          | 判断依据度、纠偏清晰度、优先级收敛、方向反复变更。            |
| 推进闭环力   | 管理者能否把讨论沉淀为 owner 明确、DDL 明确、优先级清晰的任务，并推动到真实交付。 | 任务定义完整率、任务延期率、任务关闭质量。                |
| 风险治理力   | 管理者能否提前识别高影响风险，推动缓释动作，及时升级阻塞并减少同类复发。           | 高等级风险识别覆盖率、缓释动作落地率、风险升级及时率、同类风险复发率。  |
| 协同调度力   | 管理者能否在跨团队、跨角色协作中快速响应、澄清依赖、同步里程碑并清理阻塞。          | 跨角色有效响应时长、关键里程碑同步率、依赖澄清时长、协同阻塞清理成功率。 |
| 组织行为健康度 | 管理者是否采用可持续、低内耗的沟通和推进方式，避免高压、羞辱、无效会议和重复催办。      | 高风险语言、公开负向反馈、深夜高压催办、重复催办、会议空转。       |

### 1.3.3 方向校准力

业务定义：评估管理者下达方向时，是否基于数据、文档、历史决议、业务事实或明确约束，而不是凭空拍板；当项目遇到异常时，是否能给出清晰、可执行的纠偏动作。

包含：依据溯源、目标纠偏、优先级收敛、方向稳定性。

不包含：最终业务结果好坏、战略是否绝对正确、上级目标本身是否合理。

核心指标：

| 二级指标     | 判断口径                                                    | 数据源锚点                                        | 阈值/提示                 |
| :------- | :------------------------------------------------------ | :------------------------------------------- | :-------------------- |
| 判断依据度    | `1 - 无依据决策数 / 总决策数`。有具体数据、文档引用、历史决议或项目事实视为有依据。          | 主：会议/妙记、云文档、Base 记录；辅：聊天历史；校验：Base 历史。       | 无依据决策占比高时触发方向校准风险。    |
| 目标纠偏清晰度  | 异常后 48 小时内的纠偏动作是否包含 owner 和 DDL，缺任一项视为模糊纠偏。             | 主：聊天历史、会议/妙记、Base 风险记录；辅：云文档复盘；校验：Base 历史。   | 模糊纠偏率高时触发人工复核。        |
| 优先级收敛时长  | 从首次优先级分歧到形成统一口径并落盘的时间差。                                 | 主：聊天历史、会议/妙记；落盘校验：Base 记录、Base 历史；辅助：日历会议时间。 | v1 健康阈值建议为 24 小时以内。   |
| 方向反复变更次数 | 同一 P0/P1 事项出现“推进 -> 暂缓/废弃 -> 重新推进”或“上线 -> 回滚 -> 再上”的次数。 | 主：Base 历史；辅：Base 记录、聊天历史、会议/妙记。              | 周期内超过 2 次视为严重方向稳定性风险。 |

降级与复核：若只有会议文本、缺少 Base 或文档依据，则只输出低置信度观察；若管理者发言与项目事实冲突，或同一事项多次反向调整，进入人工复核。

### 1.3.4 推进闭环力

业务定义：评价管理者能否把讨论沉淀为优先级清晰、owner 明确、时限明确的任务，并持续推进到真实交付与验收闭环。该维度硬数据占比最高，是 MVP 的核心维度之一。

包含：行动项沉淀、任务定义完整性、任务延期、逾期纠偏、关闭真实性。

不包含：跨团队响应速度、成员情绪管理、风险识别本身、单纯工具活跃度。

核心指标：

| 二级指标    | 判断口径                                              | 数据源锚点                                          | 阈值版本                         |
| :------ | :------------------------------------------------ | :--------------------------------------------- | :--------------------------- |
| 任务定义完整率 | 应执行事项中，已沉淀为任务且同时具备 owner、DDL、任务描述的比例；抢资源事项还需有优先级。 | 主：Base 任务记录；辅：会议/妙记 Action Item、云文档周报；补充：聊天历史。 | v1：>=85% 好，60%-85% 中，<60% 坏。 |
| 任务延期率   | 月内逾期任务数 / 月内应完成任务总数，仅统计有明确 DDL 的任务。               | 主：Base 任务记录；校验：Base 历史；辅：云文档周报、会议/妙记。          | v1：<10% 好，10%-25% 中，>25% 坏。  |
| 任务关闭质量  | 已关闭任务中，具备交付结果、验收结论、关闭留痕三项证据的任务占比。                 | 主：Base 任务记录与 Base 历史；辅：云文档周报/复盘、会议/妙记。         | v1：>=80% 好，60%-80% 中，<60% 坏。 |

降级与复核：无结构化任务表时，降级为会议/周报抽样统计并标注置信度；关闭任务数量高但验收证据不足、同一任务反复开关、纪要事项显著多于任务表时触发人工复核。

### 1.3.5 风险治理力

业务定义：衡量管理者面对业务不确定性时，能否做到早发现、早干预、早升级，并推动同类问题防复发。

包含：高等级风险识别、缓释动作、阻塞升级、复盘归因和复发治理。

不包含：确定性日常任务的按期交付率、业务复杂度本身、外部不可控事故责任归因。

核心指标：

| 二级指标       | 判断口径                                      | 数据源锚点                                                   | 阈值版本                               |
| :--------- | :---------------------------------------- | :------------------------------------------------------ | :--------------------------------- |
| 高等级风险识别覆盖率 | 实际发生的 P0/P1 高影响问题中，事前至少 24 小时被建档或明确提及的比例。 | 主：Base 风险记录、云文档复盘/周报；辅：会议/妙记、聊天历史；校验：Base 历史。           | v0.1：>=80% 健康，50%-80% 中等，<50% 风险高。 |
| 缓释动作落地率    | 生成并有实质推进记录的缓释动作数 / 已识别风险总数。               | 主：Base 风险记录与关联任务记录；校验：Base 历史；辅：会议/妙记 Action Item、聊天历史。 | v0.1：>=85% 健康，60%-85% 中等，<60% 风险高。 |
| 风险升级及时率    | 满足 SLA 条件的阻塞事项中，在规定时间内完成升级的比例。            | 主：Base 风险记录、聊天历史风险升级群；辅：会议/妙记、云文档升级标记；时间校验：Base 历史。     | v0.1：>=90% 健康，70%-90% 中等，<70% 需关注。 |
| 同类风险复发率    | 周期内被归因为同类根因复发的风险占比，反向指标。                  | 主：Base 风险记录、云文档复盘/周报；辅：会议/妙记；历史校验：Base 历史。              | v0.1：<10% 健康，10%-25% 中等，>25% 需关注。  |

降级与复核：周期内没有高影响问题时不计算覆盖率，只输出暂无样本；风险话术模糊且匹配置信度低于 0.7 时判为未识别；重大事故复盘大量外部归因、缓释任务大面积烂尾、出现“先压下来”等掩饰性指令时触发人工复核。

### 1.3.6 协同调度力

业务定义：评价管理者能否在跨团队、跨角色、跨模块协作中快速建立响应、澄清依赖、同步关键里程碑并清理阻塞。

包含：跨角色响应、里程碑同步、依赖边界澄清、跨团队阻塞清理、因沟通偏差导致的返工。

不包含：单团队内部任务闭环、风险识别本身、资源投入是否充足、成员情绪管理。

核心指标：

| 二级指标      | 判断口径                                             | 数据源锚点                                         | 阈值版本                                          |
| :-------- | :----------------------------------------------- | :-------------------------------------------- | :-------------------------------------------- |
| 跨角色有效响应时长 | 从跨团队 @、明确求助、依赖提起到首次有效响应的平均时长；有效响应需包含接收、路径或下一步动作。 | 主：聊天历史；辅：会议/妙记、Base 记录；必要干系人校验：通讯录。           | 紧急事项 <=30 分钟好，30-60 分钟中，>60 分钟坏；常规事项 <=4 小时好。 |
| 关键里程碑同步率  | 需求冻结、排期变更、责任调整、风险升级等事项中，已同步必要干系人且形成下一步的比例。       | 主：云文档、会议/妙记、日历；辅：聊天历史、Base 记录；干系人校验：通讯录。      | v1：>=90% 好，75%-90% 中，<75% 坏。                  |
| 依赖澄清时长    | 从首次暴露依赖/边界/责任不清，到明确责任方、配合方和下一步动作的平均时间。           | 主：聊天历史、会议/妙记；落盘校验：Base 记录、Base 历史；干系人校验：通讯录。  | v1：<=2 天好，2-4 天中，>4 天坏。                       |
| 协同阻塞清理成功率 | 跨团队阻塞事项中，在窗口期内解除阻塞，或形成相关方确认的解决路径并进入执行的比例。        | 主：Base 风险/任务记录；校验：Base 历史；辅：聊天历史、会议/妙记、云文档复盘。 | v1：>=85% 好，60%-85% 中，<60% 坏。                  |

降级与复核：无结构化阻塞标签时，降级为升级记录和会议结论抽样统计；只有“收到/已读”但没有实质动作、必要干系人范围有争议、阻塞关闭缺少解除证据时触发人工复核。

### 1.3.7 组织行为健康度

业务定义：衡量管理者在日常协作和向下管理中，是否采用可持续、低内耗的沟通机制，管理风格是否偏赋能驱动而非高压/情绪驱动。

包含：负向语言、公开负向反馈、非常规时段高压催办、重复催办、会议空转。

不包含：最终业务指标是否达成、人格评价、情商评价、跨部门利益分配策略。

核心指标：

| 二级指标      | 判断口径                                               | 数据源锚点                                     | 阈值版本                         |
| :-------- | :------------------------------------------------- | :---------------------------------------- | :--------------------------- |
| 高风险语言触发频次 | 命中公开羞辱、甩锅免责、威胁式压迫、人身攻击等分类库的次数。                     | 主：聊天历史、会议/妙记；辅：云文档纪要。                     | 0 次健康，1-2 次观察，>=3 次需人工复核。    |
| 公开负向反馈占比  | 公开场景下针对具体个人的负向评价消息数 / 公开场景下全部反馈消息数。                | 主：聊天历史、会议/妙记；场景校验：日历参与人、通讯录。              | <20% 健康，20%-40% 中等，>40% 需关注。 |
| 深夜高压催办占比  | 22:00 至次日 08:00 及周末非发版日的催办消息数 / 全部催办消息数。           | 主：聊天历史时间戳；辅：日历、Base 任务 DDL；必要时用会议/妙记补上下文。 | <10% 健康，10%-25% 中等，>25% 风险高。 |
| 重复催办率     | 同一事项在未到 DDL 且无信息增量情况下的重复催问次数 / 该事项总催问次数。           | 主：聊天历史；校验：Base 任务记录、Base 历史；辅：会议/妙记。      | <15% 健康，15%-30% 中等，>30% 需关注。 |
| 会议空转率     | 缺失结论/Next Step、Owner、DDL 中任意两项的会议数 / 管理者发起的主题会议总数。 | 主：会议/妙记、云文档纪要；辅：日历、Base 任务记录。             | <10% 健康，10%-25% 中等，>25% 风险高。 |

降级与复核：文本缺上下文时标记低置信度，不计入强结论；头脑风暴、信息同步、茶话会等明确非决策会议可豁免会议空转统计；出现人身攻击、合规红线、连续深夜高压催办、单人被持续公开负向反馈时必须人工复核。

### 1.3.8 综合输出和附加观察项

主评估结构以 5 个一级维度为准。旧稿中的“事实依据力”不再作为独立主维度，而是横向成为每条结论的证据充分性和置信度要求。

`AI 替代风险指数` 保留为衍生观察项，用于描述“低质量同步、重复催办、方向判断弱、风险治理弱、闭环推动弱”等行为组合带来的岗位重设计风险。该指数不参与 5 维主评分机械加总，不输出“建议裁撤”等人事结论，只输出辅导、流程重构、AI 工具协同或岗位重设计建议。

# 2. IO 设计

## 2.1 输入内容

### 2.1.1 输入优先级

MVP 输入源收敛为 7 类：

`Base 记录 > Base 历史 > 云文档 > 会议/妙记 > 聊天历史 > 日历 > 通讯录`

原则：

- Base 记录优先用于硬指标计算，例如 owner、DDL、状态、风险等级、关闭留痕。
- Base 历史优先用于状态变更、延期、reopen、方向反复和落盘时间校验。
- 云文档用于校验方向依据、周报/复盘、风险根因、里程碑和会议纪要归档。
- 会议纪要/妙记优先用于识别决策、行动项、风险信号、协同讨论和组织行为。
- 聊天历史主要用于响应时长、公开反馈、深夜催办、风险升级、优先级分歧和线下补录线索。
- 日历用于会议时间、参会人、必要干系人是否被邀请、非常规时段会议和里程碑窗口校验。
- 通讯录用于识别评估对象、上下级、跨部门协作关系和必要干系人范围。

### 2.1.2 数据源清单

| 数据源     | MVP 输入内容                               | 用途                          |
| :------ | :------------------------------------- | :-------------------------- |
| Base 记录 | 项目、任务、风险、会议、Statements 等表的当前记录。        | 硬指标计算、评估对象定位、任务/风险/会议事实。    |
| Base 历史 | 记录字段变更、状态流转、owner/DDL 调整、reopen/关闭轨迹。  | 状态变更校验、方向反复、延期和关闭质量判定。      |
| 云文档     | 需求文档、项目方案、周报、复盘、评审结论、计划变更记录。           | 依据溯源、结果校验、风险根因和历史复核。        |
| 聊天历史    | 项目群、部门群、风险升级群、关键决策讨论串、线下补录线索。          | 响应时长、公开反馈、催办、升级证据、优先级收敛。    |
| 会议/妙记   | 会议检索结果、会议纪要、妙记摘要、转写片段、Action Item、参会人。 | 方向校准、闭环沉淀、协同和行为审计。          |

| 通讯录     | 用户、部门、上下级、项目角色、跨部门协作关系。                | RACI 判断、协同边界、必要同步范围和公开场景识别。 |

## 2.2 输出内容

MVP 输出分为两层：

- 面向业务的最终交付：单次评估结果、周期评估报告、风险提示、人工复核项。
- 面向系统运行的中间成果物：`task_request`、`input_completeness_report`、`orchestration_state`、`raw_payload`、`history_bundle`、`meeting_fact_pack`、`data_quality_report`、`hard_metrics_result`、`evaluation_plan`、各 Agent result、`capability_assessor_result`、`report_result`、`automation_summary`、`observability`。

其中 `report_result` 是当前 MVP 最终交付的主产物，必须覆盖 PRD 五个维度下全部指标，并给出每个指标的具体数值和证据源。

### 2.2.1 单次评估结果

用于一次会议或一次人工触发任务后的结构化输出。

```json
{
  "evaluation_id": "string",
  "project_id": "string",
  "manager_id": "string",
  "dimension_findings": [
    {
      "dimension": "方向校准力",
      "rating": "好/中/坏/暂无样本",
      "score": 0,
      "confidence": 0.0,
      "key_evidence": [],
      "risk_tags": [],
      "recommended_actions": []
    }
  ],
  "indicator_results": [
    {
      "dimension": "方向校准力",
      "indicator_id": "judgment_basis_degree",
      "indicator_name": "判断依据度",
      "value": 0.9444,
      "unit": "ratio",
      "status": "available/degraded/no_sample/missing",
      "score": 88,
      "confidence": 0.84,
      "evidence_refs": [
        "04_meetings/base_statements_record_list.json#statement_id=stmt_001",
        "02_chats/im_messages_search_user.json#message_id=om_xxx"
      ]
    }
  ],
  "risk_flags": [],
  "human_review_items": [],
  "ai_replacement_risk_observation": {
    "level": "低/中/高/不判断",
    "reason": "string"
  }
}
```

补充要求：

- `dimension_findings` 用于表达维度结论。
- `indicator_results` 用于表达 PRD 指标层结果，当前要求覆盖 20 个指标。
- 每个指标必须至少包含 `value`、`unit`、`status` 和 `evidence_refs`；软指标额外建议包含 `score` 和 `confidence`。
- 当模型正文生成失败时，系统仍需保底输出 `indicator_results` 和基础证据链，不得因为报告文案失败而丢失指标结果。

### 2.2.2 周期评估报告

用于每周或指定周期向 HRBP、PMO、上级管理者输出。报告包含：

- 管理者和项目基本信息。
- 五维评分和趋势箭头。
- 五个维度下全部指标的数值表、状态和证据源摘要。
- 关键证据摘要。
- 本周期高风险行为或管理风险。
- 与上周期相比的改善或恶化项。
- 建议动作和下一周期观察重点。

### 2.2.3 风险提示/预警

用于风险治理、组织行为或高影响结论触发时的即时提醒。预警必须包含：

- 触发原因。
- 关联项目、任务、风险或会议。
- 证据片段和来源。
- 置信度。
- 建议处理人。
- 是否需要审批后发送。

### 2.2.4 人工复核项与证据链

用于 Base 人工复核台。复核对象统一结构为：

```json
{
  "review_item_id": "string",
  "evaluation_id": "string",
  "trigger_reason": "证据冲突/低置信度/高风险语言/敏感结论/输出冲突",
  "disputed_evidence": [],
  "agent_recommendation": "确认/驳回/降级/补充证据",
  "human_decision": "pending/confirmed/rejected/downgraded",
  "human_comment": "string"
}
```

### 2.2.5 报告对象分型

| 报告类型  | 受众            | 内容范围                    | 审批要求          |
| :---- | :------------ | :---------------------- | :------------ |
| 摘要版   | 上级管理者、PMO     | 五维结论、风险标签、关键建议。         | 中风险以上建议审批。    |
| 完整版   | HRBP、项目治理负责人  | 全量证据链、维度口径、人工复核记录、趋势分析。 | 高风险结论必须审批。    |
| 风险提示版 | 项目负责人、上级、HRBP | 单一风险事件、证据、建议动作。         | 涉及组织行为红线必须审批。 |

# 3. 任务定义

## 3.1 任务名

`中层管理效能评估任务`

## 3.2 触发条件

MVP 支持 4 类触发：

1. 事件触发
   - 新会议纪要/妙记生成。
   - 项目周会结束。
   - 关键项目状态更新。
   - 风险任务逾期、阻塞或升级。
2. 周期触发
   - 每周固定生成周期评估报告。
   - 项目周会结束后自动生成单次评估。
3. 人工触发
   - 上级管理者主动发起评估。
   - PMO/HRBP 对某项目负责人发起专项审查。
   - 项目治理负责人要求复核某个风险或争议结论。
4. 风险触发
   - 连续多次会议无有效行动项。
   - 管理者发言与项目事实冲突。
   - 项目延期加剧且缺少纠偏动作。
   - 出现高风险语言、公开负向反馈集中、深夜高压催办等组织行为风险。

## 3.3 成功标准

满足以下条件，任务视为完成：

1. 已获取目标管理者在指定周期内的授权数据。
2. 已完成会议发言、项目任务、风险、文档依据的结构化抽取。
3. 已完成同项目最近 3 到 5 场会议或历史材料复核；若无法完成，已进入降级状态并说明原因。
4. 已完成五个主维度评估，或明确标记暂无样本/不计算。
5. 已为每个结论关联关键证据、置信度、风险标签和建议动作。
6. 已生成至少一类报告：单次评估结果、周期评估报告或风险提示。
7. 已处理所有命中规则的人工复核项，或明确等待人工审批。
8. 已生成 `report_result` 和可消费的 `base_writeback_payload`；若在线回写链路可用，则需完成 Base 回写。

## 3.4 失败标准

满足以下任一条件，任务视为失败或未完成：

1. 无法获取必要数据源，导致核心结论不成立。
2. 证据不足但仍输出高确定性结论。
3. 未完成历史复核却直接输出高风险定性结论。
4. 未生成最终 `report_result` 或可回写 payload，导致流程中断。
5. 报告缺少依据说明、证据引用错误或引用对象错配。
6. 越权访问未授权数据。
7. 超过任务时限仍未进入可交付、降级或待审批状态。

## 3.5 简版状态机

```text
待命
  ↓
接收任务
  ↓
输入检查
  ↓
拉数
  ↓
硬指标计算
  ↓
规划
  ↓
专家分析
  ↓
汇总收口
  ↓
自检
  ↓
人审/降级
  ↓
完成
```

状态说明：

| 状态             | 进入条件                               | 退出条件                                                                                          |
| :------------- | :--------------------------------- | :-------------------------------------------------------------------------------------------- |
| 待命             | 无运行任务。                             | 收到事件、周期、人工或风险触发。                                                                              |
| 接收任务           | Master Agent 已获得评估对象、项目、周期。        | 形成 `orchestration_state`。                                                                     |
| 输入检查           | 已收到评估任务。                           | 生成 `input_completeness_report`，确认权限、文件和样本量。                                                   |
| Front Pipeline | 输入检查通过，或允许降级运行。                    | `task_request`、`raw_payload`、`meeting_fact_pack`、`history_bundle`、`data_quality_report` 生成完成。 |
| 硬指标计算          | 事实包和 Base 快照可用。                    | 生成 `hard_metrics_result`。                                                                     |
| 规划             | 事实包、历史包和硬指标结果可用。                   | 生成 `evaluation_plan`，其中包含 `evaluation_focus`、`execution_plan` 和 `human_review_rules`。         |
| 专家分析           | 评估计划可用。                            | 生成专家 Agent 的 `dimension_findings`、`soft_indicators`、`risk_flags`、`human_review_items`。        |
| 汇总收口           | 专家输出完成。                            | Master Agent 汇总状态，Capability Assessor 形成 `dimension_scores` 和综合结论。                            |
| 自检             | 综合输出完成。                            | JSON 合法、证据齐全、置信度和敏感规则检查完成。                                                                    |
| 人审/降级          | 命中复核规则、工具失败或数据不足。                  | 人工确认或系统输出降级结果。                                                                                |
| 完成             | `report_result` 生成，且已完成回写或形成可回写载荷。 | 进入下一周期观察。                                                                                     |

# 4. 代理边界

## 4.1 脚本负责

脚本和确定性工具负责稳定、重复、可计算的工作：

- 飞书 Base、文档、会议纪要和聊天样本的数据读取。
- 数据清洗、去重、时间线排序、字段标准化。
- owner、DDL、任务状态、逾期、关闭、风险等级等硬指标计算。
- JSON Schema 校验、报告模板渲染、Base 写回、消息发送。
- 运行日志、错误码、API 成功率和任务耗时记录。

## 4.2 LLM 负责

LLM Agent 负责需要语义理解、判断、归因和表达的工作：

- 识别会议中的决策点、纠偏动作、风险信号、依赖争议和组织行为片段。
- 判断决策是否有依据、纠偏是否清晰、风险是否被提前识别。
- 对任务关闭真实性、协同阻塞清理、会议空转等混合指标做证据归纳。
- 生成维度结论、置信度、风险标签和建议动作。
- 将结构化结果转写为管理者可读报告。

## 4.3 人负责

人负责目标、权限、边界和最终使用：

- 定义评估目的、适用范围、使用对象和报告受众。
- 配置数据权限、审批规则、风险策略和阈值版本。
- 审核高风险、低置信度、敏感或争议结论。
- 决定是否基于报告进行辅导、项目治理或流程调整。
- 对 Agent 输出进行反馈标注，帮助后续调优。

## 4.4 明确不由 Agent 负责

- 不直接做干部任免、人事处分、绩效定级。
- 不评估人格、忠诚度、情商等不可验证特质。
- 不在证据不足时进行推断性定性。
- 不绕过审批访问未授权数据。
- 不输出组织级横向排名。

# 5. Agent 设计

MVP 当前运行态固定为 `Evaluation Automation + Front Pipeline + Hard Metrics Engine + Evaluation Planner + 3 个专家 Agent + Capability Assessor + Report Writer`。其中前 4 个是流程/规则节点，后 5 个是真正调用模型的 LLM Agent。

## 5.1 Agent 名称总览

| 节点                                          | 类型               | 定位                                               |
| :------------------------------------------ | :--------------- | :----------------------------------------------- |
| Evaluation Automation / Master Orchestrator | 工作流编排节点          | 接收评估对象、周期、项目范围，检查输入完整性，调度硬指标和专家 Agent，汇总结果并触发报告。 |
| Front Pipeline                              | 工作流节点            | 输入检查、拉数、清洗、结构化事实包、历史包和数据质量报告。                    |
| Hard Metrics Engine                         | 代码/规则节点          | 计算 15 个确定性硬指标，输出分子、分母、样本口径和缺口。                   |
| Evaluation Planner                          | 规则节点             | 判断本次评估重点、执行计划和复核策略。                              |
| Management Reviewer                         | LLM Agent        | 分析方向校准力、推进闭环力中的管理动作和闭环证据。                        |
| Risk & Behavior Auditor                     | LLM Agent        | 分析风险治理力和组织行为健康度。                                 |
| Coordination Lens                           | LLM Agent        | 对跨角色响应、里程碑同步、依赖澄清和阻塞清理做协同调度专项判断。                 |
| Capability Assessor                         | LLM Agent        | 汇总硬指标、软指标和专家结论，形成五维评分、总评和附加观察项。                  |
| Report Writer                               | LLM Agent + 保底规则 | 生成摘要版、完整版、风险提示版报告，输出 20 个 PRD 指标结果并组织回写内容。       |

## 5.2 标准接口字段

系统内部统一使用以下字段，避免旧维度口径混杂：

| 字段                          | 生成方                          | 消费方                                                  | 说明                          |
| :-------------------------- | :--------------------------- | :--------------------------------------------------- | :-------------------------- |
| `orchestration_state`       | Master Agent / Orchestrator  | 全流程节点                                                | 当前评估任务的状态、下一步动作、失败/降级状态。    |
| `input_completeness_report` | Master Agent / Orchestrator  | Front Pipeline、Human Review                          | 输入文件、权限、样本量和必填字段检查结果。       |
| `task_request`              | Front Pipeline               | 全流程节点                                                | 本次评估任务的项目、负责人、会议、触发方式和时间窗口。 |
| `raw_payload`               | Front Pipeline               | Hard Metrics Engine、各分析 Agent、Report Writer          | 标准化后的原始输入总包。                |
| `meeting_fact_pack`         | Front Pipeline               | Evaluation Planner、各分析 Agent                         | 当前会议的结构化事实包。                |
| `history_bundle`            | Front Pipeline               | Evaluation Planner、各分析 Agent                         | 同项目历史会议、历史风险、过往评估和复盘材料。     |
| `data_quality_report`       | Front Pipeline               | Evaluation Planner、Capability Assessor、Report Writer | 数据质量、样本缺口和降级原因。             |
| `hard_metrics_result`       | Hard Metrics Engine          | Evaluation Planner、专家 Agent、Capability Assessor      | 确定性硬指标计算结果和样本口径。            |
| `evaluation_plan`           | Evaluation Planner           | 各分析 Agent、Capability Assessor、Report Writer          | 本次重点维度、执行顺序、人工复核规则和降级策略。    |
| `dimension_findings`        | 分析 Agent、Capability Assessor | Report Writer、Base                                   | 五维结论、评分、证据、置信度、建议动作。        |
| `soft_indicators`           | 各专家 Agent                    | Capability Assessor、Report Writer                    | 由专家语义判断产出的软指标，最终要与硬指标一起交付。  |
| `risk_flags`                | 分析 Agent、Capability Assessor | Report Writer、Human Review                           | 高风险管理信号、组织行为信号、项目治理风险。      |
| `human_review_items`        | 各 Agent                      | Human Review、Base                                    | 待人工确认、驳回、降级或补充的复核项。         |
| `dimension_scores`          | Capability Assessor          | Report Writer、Base                                   | 五维分数、等级和支持证据。               |
| `indicator_results`         | Report Writer                | 报告、Base、展示层                                          | PRD 五个维度下所有指标的数值、状态和证据源。    |
| `report_result`             | Report Writer                | 文档、消息、Base、观测层                                       | 最终报告内容、指标表和回写载荷。            |

## 5.3 Evaluation Automation / Master Orchestrator

职责：

- 接收评估对象、评估周期、项目范围和报告受众。
- 检查输入文件是否齐全，包括 Base 表、会议纪要、项目文档、周报/复盘和必要聊天样本。
- 判断任务是否可以全量运行、降级运行或需要人工补充材料。
- 调用 Front Pipeline、Hard Metrics Engine、Evaluation Planner 和专家 Agent。
- 汇总各节点运行状态，处理失败、超时、低置信度和人工复核分支。
- 在 Capability Assessor 形成综合结论后，触发 Report Writer 生成报告，并推动 Base 回写。

输入：

- 评估对象、项目 ID、评估周期、报告类型、受众范围。
- 人工触发参数、周期触发参数或风险触发事件。

输出：

- `orchestration_state`
- `input_completeness_report`
- 节点调用计划。
- 任务完成、降级、失败或待人工处理状态。

交接条件：

- 输入齐备时进入 Front Pipeline。
- 输入缺失但可降级时标记降级原因后继续。
- 输入缺失导致核心结论不成立时，停止任务并生成补充材料清单。

## 5.4 Front Pipeline / Data Collector

职责：

- 生成 `task_request`、`input_completeness_report` 和 `orchestration_state`。
- 拉取当前会议妙记、项目主文档、周报、复盘、同项目历史会议材料。
- 读取 Base 中项目、任务、风险、评估结果、报告状态数据。
- 将非结构化内容转成统一结构化事实包。
- 为后续 Agent 准备 `raw_payload`、`history_bundle`、`meeting_fact_pack` 和 `data_quality_report`。

输入：

- 评估对象、项目 ID、评估周期。
- Base 项目/任务/风险/评估/报告快照。
- 当前会议纪要/妙记、项目文档和历史材料。

输出：

- `task_request`
- `input_completeness_report`
- `orchestration_state`
- `raw_payload`
- `meeting_fact_pack`
- `history_bundle`
- `data_quality_report`

交接条件：

- 数据源读取成功，或明确记录失败数据源和降级原因。
- 事实包中每条结构化事实都保留来源 ID、时间戳和原文索引。

## 5.5 Hard Metrics Engine

职责：

- 对确定性指标进行代码/规则计算，不调用 LLM 做主判断。
- 当前实现中固定输出 15 个硬指标；PRD 中其余软指标由专家 Agent 计算，再由 Report Writer 汇总成完整 20 指标结果。
- 计算任务定义完整率、任务延期率、任务关闭质量。
- 计算风险升级及时率、缓释动作落地率、同类风险复发样本量。
- 计算跨角色有效响应时长、关键里程碑同步率、依赖澄清时长、协同阻塞清理成功率的可计算部分。
- 计算深夜高压催办占比、重复催办率、会议空转率等频次和比例指标。
- 输出每个指标的分子、分母、样本口径、缺失字段和异常值。

输入：

- `meeting_fact_pack`
- `history_bundle`
- Base 项目/任务/风险快照和 Base 历史。
- 聊天历史时间戳和消息结构化结果。
- 日历事件、会议/妙记和通讯录角色信息。

输出：

- `hard_metrics_result`
- `metric_quality_report`
- 指标缺口和异常样本清单。

交接条件：

- 可计算指标必须输出分子、分母和时间窗口。
- 无有效样本的指标必须标记 `暂无样本`，不得用 0 分替代。
- 指标缺口需传给 Evaluation Planner 和 Capability Assessor。

## 5.6 Evaluation Planner

职责：

- 根据当前会议、项目状态、风险变化和历史评估结果，决定本次评估重点。
- 判断本次应走全量评估、轻量周报、专项风险审计或组织行为复核。
- 生成后续 Agent 的执行计划和人工复核策略。

输入：

- `meeting_fact_pack`
- `history_bundle`
- `hard_metrics_result`
- 项目状态、风险等级、上一次人工反馈。

输出：

- `evaluation_plan`
- `evaluation_focus`
- `execution_plan`
- `review_requirements`
- `human_review_rules`

交接条件：

- 已明确需要运行的维度。
- 已明确哪些结论必须进入人工复核。
- 已明确数据不足时如何降级。

## 5.7 Management Reviewer

职责：

- 提炼管理者的关键方向、判断、要求、优先级和纠偏动作。
- 判断方向是否有依据、纠偏是否具备 owner/DDL、优先级是否及时收敛。
- 分析会议结论是否沉淀为任务，任务定义是否完整，关闭是否真实。
- 调取同项目历史会议做 review，识别方向反复、闭环断裂和协同卡点。

输入：

- `meeting_fact_pack`
- `history_bundle`
- `hard_metrics_result`
- `evaluation_plan`
- Base 任务、项目状态、里程碑、会议结论。

输出：

- 方向校准力相关 findings。
- 推进闭环力相关 findings。
- `soft_indicators`
- 证据链、置信度、待复核项。

交接条件：

- 每条 finding 必须包含维度、判断、证据、置信度和建议动作。
- 涉及强负面结论时必须附带原始证据和复核建议。

## 5.8 Risk & Behavior Auditor

职责：

- 识别风险表述、预警动作、阻塞升级、缓释动作和复发线索。
- 对照风险表、周报、复盘和历史会议，判断风险是否被提前识别并有效治理。
- 审计组织行为健康度，识别高风险语言、公开负向反馈、深夜高压催办、重复催办和会议空转。

输入：

- `meeting_fact_pack`
- `history_bundle`
- `hard_metrics_result`
- `evaluation_plan`
- Base 风险表、复盘文档、聊天样本、会议逐轮对话。

输出：

- 风险治理力相关 findings。
- 组织行为健康度相关 findings。
- `soft_indicators`
- `risk_flags`
- `human_review_items`

交接条件：

- 组织行为红线必须进入人工复核。
- 风险治理结论必须区分“未发生样本”“已发生但未识别”“识别但未处理”“处理但未闭环”。

## 5.9 Coordination Lens

职责：

- 专项分析协同调度力中需要语义判断的部分。
- 判断跨角色响应是否为有效响应，而不是简单“收到/已读”。
- 判断关键里程碑是否同步到必要干系人，并形成明确下一步。
- 判断依赖澄清是否真正明确责任方、配合方和下一步动作。
- 判断协同阻塞是否已解除，或是否形成被相关方确认的解决路径。

输入：

- `meeting_fact_pack`
- `history_bundle`
- `hard_metrics_result`
- `evaluation_plan`
- Base 记录、Base 历史、聊天历史、会议/妙记、日历和通讯录/RACI 信息。

输出：

- 协同调度力相关 findings。
- `soft_indicators`
- 协同阻塞证据链。
- 需要人工复核的干系人范围争议和阻塞关闭争议。

交接条件：

- 对硬指标不能直接解释的协同样本补充语义判断。
- 与 Management Reviewer 或 Hard Metrics Engine 输出冲突时，生成复核项。

## 5.10 Capability Assessor

职责：

- 汇总五个主维度的 findings。
- 将硬指标、专家 soft indicators、风险标签和数据质量约束一起纳入打分。
- 统一评分、等级、置信度和风险标签。
- 处理跨 Agent 输出冲突。
- 生成综合结论和 `AI 替代风险指数` 附加观察项。

输入：

- Management Reviewer 输出。
- Risk & Behavior Auditor 输出。
- Coordination Lens 输出。
- `hard_metrics_result`
- `evaluation_plan`
- `data_quality_report`
- `human_review_items`
- 历史评估趋势。

输出：

- `dimension_findings`
- `dimension_scores`
- `risk_flags`
- 综合结论。
- 趋势变化。
- `ai_replacement_risk_observation`

交接条件：

- 不将低置信度 finding 纳入强结论。
- 不把 AI 替代风险指数纳入五维总分机械加总。

## 5.11 Report Writer

职责：

- 将结构化结论转写为飞书云文档和消息可读内容。
- 生成摘要版、完整版、风险提示版报告。
- 输出五个维度下 20 个指标的最终 `indicator_results`，每个指标必须包含具体数值和证据源。
- 组织 Base 回写字段和消息通知内容。
- 当模型正文失败时，仍需保底生成结构化 `report_result` 和 `base_writeback_payload`。

输入：

- `dimension_findings`
- `dimension_scores`
- `soft_indicators`
- `hard_metrics_result`
- `risk_flags`
- `human_review_items`
- `meeting_fact_pack`
- `history_bundle`
- `raw_payload`
- `evaluation_plan`
- 综合结论、证据摘要、建议动作。

输出：

- `report_result`
- `indicator_results`
- 报告正文。
- Base 回写内容。
- 消息通知内容。

交接条件：

- 报告必须说明证据来源和置信度。
- 每个 PRD 指标必须能追溯到 `evidence_refs`。
- 高风险和敏感报告必须带审批状态，不得绕过签字层直接发送。

# 7. 决策分层

系统中的决策分为目标、过程、执行、签字四层。

## 7.1 目标层

定义：为什么评、评什么、服务谁。

控制方：人。

负责角色：

- 上级管理者。
- HRBP。
- PMO。
- 系统管理员。

Agent 仅接收目标，不自定义组织考核目标。

## 7.2 过程层

定义：采用哪些维度、哪些数据、哪些流程来完成评估。

控制方：人主导，Agent 辅助。

负责角色：

- 人定义评估框架、权限边界、风险策略和阈值版本。
- Agent 按既定框架自动规划分析路径。

过程层必须确保五维口径、证据标准、人工复核规则一致，避免不同报告使用不同评价逻辑。

## 7.3 执行层

定义：拉数、清洗、分析、review 复核、打标签、生成报告、写回 Base。

控制方：Agent。

负责角色：

- Master Agent / Orchestrator。
- Front Pipeline / Data Collector。
- Hard Metrics Engine。
- Evaluation Planner。
- Management Reviewer。
- Risk & Behavior Auditor。
- Coordination Lens。
- Capability Assessor。
- Report Writer。

执行层可以自动完成低风险结论和常规报告，但必须记录日志、证据链和置信度。

## 7.4 签字层

定义：哪些结论可以正式生效、哪些结论可以发送给谁。

控制方：人。

负责角色：

- 上级领导。
- HRBP。
- 项目治理负责人。

高风险结论、敏感报告、组织行为红线和可能影响管理动作的报告必须由人签字后生效。当前 MVP 不输出组织级横向对比。

# 8. 失败和降级策略

## 8.1 工具失败

场景：

- Base 读取或写入失败。
- 会议纪要/云文档读取失败。
- 聊天样本导入失败。
- 报告生成或消息发送失败。

策略：

- 优先重试一次，并记录失败源、错误码和时间。
- 若读取失败但其他主证据可用，则降级输出局部评估。
- 若 Base 写回失败，则任务不得标记完成，只能进入“待回写”状态。
- 若报告发送失败，保留报告记录并提示人工处理。

## 8.2 数据不足

场景：

- 评估周期内会议样本过少。
- Base 任务缺少 owner、DDL 或状态。
- 风险表缺少发生时间或缓释动作。
- 组织行为语料不足。

策略：

- 指标无有效分母时输出“暂无样本”。
- 缺少主证据但有辅助证据时输出低置信度观察。
- 缺少关键证据时不输出强定性结论。
- 报告中明确列出样本缺口和下一周期补数建议。

## 8.3 低置信度

场景：

- LLM 判断置信度低于阈值。
- 证据片段短、上下文缺失或语义歧义。
- 同一事项在不同材料中表述冲突。

策略：

- 将结论降级为观察项。
- 触发 `human_review_items`。
- 不进入五维强评分或高风险标签。
- 延迟到下一周期结合更多证据复评。

## 8.4 输出冲突

场景：

- Management Reviewer、Risk & Behavior Auditor、Coordination Lens 对同一事件判断冲突。
- Base 状态与会议结论冲突。
- 周报和复盘对风险原因描述冲突。

策略：

- 以结构化系统记录为第一校验源，以会议和文档作为解释性证据。
- 生成冲突说明，标注冲突来源。
- 进入人工复核，不自动选择对管理者更有利或更不利的结论。

## 8.5 审批未通过

场景：

- 人工驳回高风险结论。
- 审批人要求补充证据。
- 报告受众范围被限制。

策略：

- 报告状态标记为“审批未通过”或“需补证”。
- 已驳回结论不得发送给原定受众。
- 保留 Agent 原始判断、人审意见和最终处理结果，用于后续调优。

## 8.6 越权风险

场景：

- 请求访问未授权项目、聊天记录或组织数据。
- 报告准备发送给未授权受众。

策略：

- 立即停止相关数据读取或发送。
- 记录越权拦截日志。
- 输出权限不足说明，不生成替代性猜测结论。

# 9. 评测体系

评测体系分为业务效果、评估准确性、系统运行、治理安全四层。

## 9.1 业务效果指标

衡量这个 Agent 是否真的带来管理改进。

| 指标        | 说明                            |
| :-------- | :---------------------------- |
| 报告采纳率     | 报告被 HRBP、PMO、上级实际查看、引用或处理的比例。 |
| 风险命中率     | Agent 提示的风险在后续被验证为真实风险的比例。    |
| 关键问题提前发现率 | 高影响问题在发生前被 Agent 提示的比例。       |
| 管理建议执行率   | 报告中的建议动作被创建任务或执行跟进的比例。        |
| 闭环改善率     | 连续周期中任务定义完整率、延期率、关闭质量等指标改善情况。 |
| 复核后结论稳定率  | 人工复核后仍保持原结论的比例。               |

## 9.2 评估准确性指标

衡量 Agent 判断是否可信。

| 指标        | 说明                        |
| :-------- | :------------------------ |
| 证据匹配准确率   | 结论引用的证据是否准确对应原始事实。        |
| 决策依据判断准确率 | 对“有依据/无依据”决策的判断是否被人工认可。   |
| 风险标签准确率   | 风险等级、风险类型和缓释动作判断是否准确。     |
| 组织行为标签准确率 | 高风险语言、公开负向反馈、重复催办等识别是否准确。 |
| 人工复核一致率   | Agent 建议与人工最终判断一致的比例。     |
| 误报率/漏报率   | 风险和行为信号的误报、漏报情况。          |

## 9.3 系统运行指标

衡量系统是否适合持续运行和比赛演示。

| 指标         | 说明                       |
| :--------- | :----------------------- |
| API 成功率    | 飞书 Base、文档、会议、消息接口调用成功率。 |
| 平均任务处理时长   | 从触发评估到报告生成的平均时间。         |
| Base 写回成功率 | 评估结果、报告、复核项成功写回比例。       |
| 自动化运行成功率   | 周期任务按计划完成的比例。            |
| 历史会议召回成功率  | 同项目最近 3 到 5 场会议成功召回比例。   |
| JSON 合法率   | Agent 输出通过 schema 校验的比例。 |

## 9.4 治理安全指标

衡量系统是否可控。

| 指标        | 说明                    |
| :-------- | :-------------------- |
| 越权调用次数    | 被权限策略拦截的数据访问或发送行为。    |
| 未审批敏感输出次数 | 敏感结论绕过审批的次数，目标为 0。    |
| 无证据强结论占比  | 缺少证据仍输出强判断的比例，目标为 0。  |
| 审计日志完整率   | 任务、证据、复核、报告、发送日志是否完整。 |
| 人工复核处理时长  | 复核项从生成到处理完成的平均时间。     |

## 9.5 五维评分展示

MVP 可采用 100 分制或好/中/坏等级制，但对用户展示时必须优先展示分维度结论，而不是只展示总分。

建议权重：

| 维度      | 建议权重 |
| :------ | :--- |
| 方向校准力   | 20%  |
| 推进闭环力   | 25%  |
| 风险治理力   | 20%  |
| 协同调度力   | 20%  |
| 组织行为健康度 | 15%  |

说明：

- 组织行为健康度虽然权重较低，但红线类事件可触发一票复核。
- `AI 替代风险指数` 作为附加观察项展示，不参与主评分机械加总。
- 所有分数必须同时展示证据摘要和置信度。

# 10. 可观测体系

可观测体系用于保证评估流程可追踪、可复盘、可调优，重点记录 5 类日志和追踪对象。

## 10.1 数据拉取日志

记录内容：

- 任务 ID、项目 ID、评估周期。
- 数据源类型、数据源 ID、读取时间、读取结果。
- 成功/失败状态、错误码、降级原因。
- 数据质量摘要，例如缺失字段、样本数量、时间范围。

用途：定位数据缺口和权限问题，支撑“为什么本次不判断”。

## 10.2 Agent 输出日志

记录内容：

- Agent 名称、输入对象版本、输出对象版本。
- `dimension_findings`、`risk_flags`、`human_review_items` 的生成时间。
- JSON schema 校验结果。
- 置信度、证据数量、敏感规则命中情况。

用途：复盘 Agent 判断过程，定位提示词、规则和模型输出问题。

## 10.3 Base 回写日志

记录内容：

- 写回表名、记录 ID、字段名、写入前后状态。
- 写回结果、失败原因、重试次数。
- 报告链接、审批状态、发送状态。

用途：保证业务流程状态不丢失，避免报告生成但 Base 未更新。

## 10.4 审批与人工复核日志

记录内容：

- 复核项 ID、触发原因、关联维度、争议证据。
- Agent 建议、人工结论、人工说明、处理人、处理时间。
- 结论是否影响最终报告和发送范围。

用途：支撑治理安全、降低误伤风险，并为后续规则调优提供标注数据。

## 10.5 关键结论证据链追踪

记录内容：

- 每条结论对应的原始会议、发言、任务、风险、文档链接。
- 证据类型：主证据、辅助证据、兜底证据。
- 证据置信度和是否被人工确认。
- 结论在后续周期是否被验证、修正或撤回。

用途：确保报告可解释、可追责、可持续学习。

## 10.6 MVP 验收检查清单

- 10 个章节均已从标题骨架补齐为可阅读内容。
- 全文统一使用方向校准力、推进闭环力、风险治理力、协同调度力、组织行为健康度五维框架。
- 每个主维度均包含定义、边界、核心指标、数据源和降级/复核策略。
- Agent 章节、Base 章节、输出章节的接口字段一致。
- 高风险结论均要求人工复核或审批。
- 文档既能支持比赛讲解，也能作为后续工程拆解依据。
